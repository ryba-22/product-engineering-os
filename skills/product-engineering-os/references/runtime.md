# Runtime contract

1. State the current outcome and classify risk R0-R4.
2. Derive the execution profile: R0/R1 -> FAST, R2 -> STANDARD, R3/R4 -> EVIDENCE_HEAVY; escalate when uncertainty/coupling/novelty/hidden failure requires it and never downgrade below the risk default.
3. Reuse current evidence/decisions before new research.
4. Inspect approved/enforced Project Constitution rules when available. Repository-local discovery creates candidates only: observed convention != approved rule != executable enforcement.
5. Route only the minimum sufficient modules and load the matching stage playbooks from references/stages/.
6. For material business behavior, run Example Mapping before implementation and preserve stable example IDs through acceptance, tests/evals and production observation.
7. For AI work touching non-public data/providers/consequential tools, classify data/provider compatibility and enforce the agent capability matrix before execution.
8. Research only unresolved questions that can materially change a decision/gate.
9. Apply stop-analysis: once the evidence threshold is met, freeze the decision and execute the smallest safe step.
10. Use canonical artifacts and decision records for material choices.
11. Before claiming VERIFIED, resolve a risk-proportional Verification Matrix across the dimensions that matter: completeness, executable tests, code/contract review, pragmatic review, reality check, production readiness and recovery.
12. Require gate evidence before advancing lifecycle state.
13. Never collapse IMPLEMENTED -> TESTED -> VERIFIED -> DEPLOYED -> HEALTHY -> SUCCESSFUL.
14. Preserve blockers, failed checks and residual risks; never silently discard them.
15. After production exposure, compare expected vs observed behavior, classify material deltas, and propagate learning to affected model/test/eval/knowledge artifacts.
16. Claim SUCCESSFUL only with Definition of Value evidence; otherwise report UNVERIFIED OUTCOME.

Operator front door: problem/outcome -> current evidence -> Project Constitution -> risk -> missing decision-changing evidence -> owner module -> execution profile -> workflow/lane topology -> Verification Matrix.

Operating profile: Activator + Focus + Discipline + Responsibility + Arranger. Situational modes: Command (unsafe progression), Restorative (bugs/incidents), Consistency (cross-project governance).
